# 公开申论真题来源与导入架构

## 1. 目标

正式题库不依赖手工逐题录入。应用使用公开可访问的申论索引发现整卷来源，并在用户本机按需读取、解析、核验后导入训练题库。

**正式产品目录只保留滚动最近 10 个自然年。**

例如 2026 年运行时，公开题库范围为 **2017—2026**；进入 2027 年后自动滚动为 2018—2027。更早真题不作为正常训练目录目标，也不再为过老页面格式投入优先开发资源。

核心链路：

`公开索引 → 近10年来源候选 → 本机受限抓取 → 整卷解析 → 人工结构核验 → 一卷多题导入 → 来源追溯`

GitHub 仓库只保存：

- 来源提供方规则；
- URL / 年份 / 地区 / 卷别等元数据结构；
- 解析器、校验器、导入器；
- synthetic / 极短测试 fixture。

GitHub 仓库不批量打包第三方整卷全文。

## 2. 当前主来源策略

### Primary：公开真题库（gwy.gkzhenti.cn）

用途：近10年整卷发现 + 结构化正文导入。

原因：

- 有统一“申论”总索引；
- 可继续进入国考、联考与各地区索引；
- 单卷结构规律，通常明确区分“给定材料”和“作答要求”；
- 材料常以 `材料1(...) / 材料2(...)` 标识；
- 作答题常包含分值和字数限制。

### Secondary：132公考、人民网等

用途：

- 近10年来源交叉核验；
- 补充主来源缺失的地区/卷别；
- 后续开发单独 adapter。

在没有来源专用 parser 前，不把这些站点的全文直接自动写入正式题库。

### Source index：公务员笔试真题来源库等

用途：只发现/追溯原始出处，不把索引站正文视为原始真题。

## 3. 时间范围规则

公开真题候选发现采用滚动窗口：

`currentYear - 9 <= year <= currentYear`

当前实现还会在 UI 再过滤一次，因此即使本机此前缓存过更老来源，也不会进入正常“公开整卷”训练目录。

旧年份解析规则可以保留作为回归兼容，但不再作为正式覆盖率目标。

## 4. 数据隔离

### `public_source_candidates`

保存网上发现的整卷候选：

- provider
- title
- source URL
- year
- region
- paper variant
- recall-version 等 metadata
- workflow status

重复扫描不得把 `reviewed / imported / rejected` 降回 `discovered`。

### `question_sources`

保存某一道本地训练题的来源证明：

- source URL
- source title/name
- retrieved/imported time
- content hash
- recall-version 标记
- rights/use note

### `public_source_question_links`

一张申论整卷通常包含 4–5 道作答题，因此使用：

`candidate_id + task_index ↔ local question_id`

而不是错误的一来源一题关系。

## 5. 整卷解析原则

### 必须识别

- 给定材料章节或可靠材料边界；
- 至少一则材料；
- 作答要求章节或可靠题号边界；
- 至少一道作答题；
- 每题分值；
- 每题字数限制；
- 非作文题的明确材料引用，或进入人工确认流程。

### 必须清理

- 导航；
- 登录/下载按钮；
- 站点 footer；
- 备案号；
- 网站版本；
- 与卷面无关的推荐内容。

解析 warning 未清零时，V0.1 不允许绕过校验直接自动导入。

## 6. 为什么每道题保留整卷全部材料

正式考试中，考生拿到的是完整给定资料，而不是系统提前过滤好的“相关材料”。

因此当前公开整卷导入后：

- 第 1 题、第 2 题……各自成为独立训练题；
- 每一道题都保留该卷完整材料；
- task 中仍记录它显式引用的材料编号，供后续分析和评分诊断使用；
- 不通过删减材料向考生泄露“哪些段落一定有用”。

## 7. 人工核验门槛

来源被抓取后不能直接写入正式题库。

UI 必须先显示：

- 材料数量；
- 作答题数量；
- 每题 prompt；
- 每题题型推断；
- 分值；
- 字数；
- 材料引用；
- parser warnings。

只有用户明确确认“与原始公开卷面一致”后，才执行整卷导入。

## 8. 幂等与失败恢复

导入使用 `candidate_id + task_index` 作为进度依据，并为公开来源题使用确定性 Question ID。

如果一张 5 题整卷在第 3 题发生失败：

- 已保存的第 1、2 题不删除；
- candidate 不标记为完整 imported；
- 再次执行时复用已存在的确定性题目 ID；
- 只继续缺失的题；
- 全部 task index 存在后才标记整卷 imported。

## 9. 与 AI 评分 / Human Gold 的边界

**公开真题正文足以作为训练题库，不等于公开网页答案可以作为评分真值。**

规则：

- 真题材料和题干可以进入训练题库；
- 站点/机构答案不得自动写成人工 Gold；
- 如后续保存站点参考答案，只能作为有来源记录的 optional reference answer；
- 正式校准仍由独立 Human Gold 流程完成；
- Stage 1–4 不读取参考答案；Stage 5 才允许交叉核验。

## 10. 网络安全边界

桌面抓取器不是通用浏览器代理。

当前：

- HTTPS only；
- host allow-list；
- 禁止 IP literal；
- 禁止 URL 内嵌 credentials；
- 不跟随 redirect；
- 单页最大 4 MB；
- HTML/plain/xhtml 与 PDF 分流；
- PDF 不伪装成 HTML 解析。
