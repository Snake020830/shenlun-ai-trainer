# UI Direction — 申论训练助手 V0.1

## 1. 产品气质

目标不是“AI 聊天窗口”或通用后台，而是长期使用的桌面学习工具：

- 安静、克制、可信；
- 以阅读、作答、复盘为视觉中心；
- 高信息密度，但不拥挤；
- 重要状态一眼可见，装饰不抢注意力；
- 主训练流程与 Benchmark / 开发工具分层。

当前基础视觉采用纸张感暖白、低饱和绿色、少量琥珀色提示，不使用强渐变、大面积高饱和色或游戏化视觉。

## 2. 页面优先级

### 一级：核心训练页

材料 / 作答 / 批改三栏是最重要页面。视觉目标：

- 材料阅读舒适；
- 答案输入区域足够安静；
- 提交前不泄露要点；
- 批改结果层级清晰；
- 长时间使用不过度刺激。

这里原则上不放装饰性插画。

### 二级：今日训练 / 题库 / 历史 / 复盘

允许更明显的卡片层级、状态徽章和轻量动效，但仍保持学习软件气质。

### 三级：设置 / Benchmark Lab

可以使用更技术化的信息结构。Benchmark Lab 是高级工具，不应该污染普通训练体验。

## 3. 生图模型适合做什么

生图模型不是 React 页面代码生成器。适合用于：

1. 应用图标 / 品牌符号候选；
2. 空状态或 onboarding 的少量插画；
3. 视觉方向探索图，用来比较“更学术 / 更现代 / 更纸张感”等路线；
4. 用户提供真实应用截图后，生成改版概念图作为设计参考。

生成图只作为视觉参考，最终页面仍必须转成真实 HTML/CSS/React，并重新做可用性与响应式验收。

## 4. 不应该用生图替代的内容

- 作答工作台；
- 表单；
- 导航；
- 批改卡片；
- 数据表；
- Benchmark / Alignment 编辑器；
- 字数、错误状态、按钮反馈。

这些必须是真实组件，否则会出现“图片很好看、产品不能用”的假完成。

## 5. 当前真实 UI polish

V0.1 已加入一层可逆视觉优化：

- 中文衬线标题字体栈；
- 全局 focus-visible；
- 统一阴影 token；
- Sidebar active indicator；
- 卡片 hover 与按钮反馈；
- 阅读区 / 批改区滚动条；
- Answer focus 状态；
- prefers-reduced-motion 支持；
- Benchmark Experiment / Human Gold / Human Alignment 使用一致的层级与状态语言。

## 6. 下一次视觉验收方法

不要只看设计稿。优先使用 GitHub Actions 生成的 Windows Preview：

1. 在 1440×900 查看默认桌面布局；
2. 缩小到 1080×720 查看最小支持尺寸；
3. 分别截图今日训练、题库、三栏作答、提交后批改、训练历史、设置、Benchmark Lab；
4. 检查层级、留白、对齐、字体、溢出、按钮状态和长文本；
5. 若整体气质仍不满意，再基于这些真实截图做视觉概念稿，并把选中的方向翻译回 CSS。

这比先生成一张“漂亮 App 图”再反推代码更可靠。
