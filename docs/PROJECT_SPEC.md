# 申论 AI Trainer — V0.1 产品规格

## 当前目标

先做一个真正可用的申论训练桌面软件，而不是先做一个聊天式 AI 批改器。

V0.1 当前闭环：

1. 从“今日训练”或“题库”选择题目；
2. 也可以手工粘贴题干与材料，建立本地题目；
3. 阅读材料并在独立作答区输入答案；
4. 草稿自动保存在本机；
5. 提交后显示结构化模拟批改；
6. 作答、得分和当次批改快照进入“训练记录”；
7. 未覆盖要点自动进入“错题复盘”；
8. 可以打开历史记录查看原答案与当次反馈，并重新作答。

## 信息架构

- 今日训练：推荐题、训练连续性、近期状态。
- 题库：内置样题 + 本地导入题，支持搜索与训练入口。
- 题目导入：手工录入题目信息、作答要求和多段材料。
- 作答工作台：材料、作答、批改三栏；提交前隐藏得分要点。
- 错题复盘：按当次批改中的遗漏/部分覆盖要点生成复盘队列。
- 训练记录：保存每次作答、得分和批改快照，可进入详情页。
- 设置：后续接模型提供商、本地数据位置、批改严格度和隐私选项。

## 数据原则

- 每次提交都保存 review snapshot，历史记录不能因未来评分模型变化而被静默重算。
- 旧 V0.1 记录若没有 review snapshot，可在对应题目仍存在时临时重建模拟反馈。
- 本地导入题没有人工标准要点时，不冒充内容评分，只给通用模拟反馈并明确标识。
- UI 只依赖 persistence adapter，不直接依赖 localStorage 或未来 SQLite 实现。

## 技术栈

- Desktop: Tauri 2
- Frontend: React + TypeScript + Vite
- Persistence V0.1: persistence adapter + localStorage
- SQLite: 已建立 V1 DDL 草案（questions / materials / drafts / training_records），尚未启用运行时数据库
- AI: 后续采用 OpenAI-compatible provider abstraction
- CI: GitHub Actions 前端 build gate（TypeScript + Vite）

## 设计原则

- 正式训练时不提前暴露评分要点，防止提示效应。
- 批改输出必须结构化：分数只是结果，要点—材料依据—修改建议才是核心。
- 所有数据来源、老师答案、模型反馈未来都应保留 provenance。
- UI 不直接依赖具体模型或存储实现。
- 模拟评分必须显式标注为模拟，不把关键词规则包装成真实 AI 判断。

## 尚未进入 V0.1 的能力

- 真实 AI 材料理解与评分引擎；
- 标准答案/老师答案导入与评分后对照；
- PDF、图片、OCR 真题导入；
- 正式 SQLite adapter 与迁移机制；
- 错误分类 taxonomy、能力画像、自适应推荐；
- 模考计时、套题与整卷训练。
