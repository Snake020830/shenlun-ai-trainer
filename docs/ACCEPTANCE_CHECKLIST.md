# 申论训练助手 V0.1 验收清单

这份清单用于验收“真实可运行产品”，不是只看代码或 CI。建议每次重要版本都按同一顺序复测，并把发现的问题记录到 PR / Issue。

## A. 安装与启动

- [ ] 阶段验收时从 GitHub Actions 的 Desktop CI 下载最新 `Shenlun-Trainer-Windows-Preview` artifact。
- [ ] 解压并运行其中的 NSIS `-setup.exe` 安装包。
- [ ] 安装名称显示为“申论训练助手 Preview”，不会覆盖未来正式版。
- [ ] 首次启动无白屏、闪退、控制台错误弹窗。
- [ ] 1440×900 窗口下布局完整；缩到 1080×720 后关键操作仍可见。
- [ ] 日常 UI 验收可使用本地仓库 `start-local-preview.cmd`，不要求反复下载安装包。

## B. 今日训练 / 题库

### B1. 已入库题目

- [ ] 左侧导航可进入：今日训练、题库、错题复盘、训练记录、设置。
- [ ] 今日训练卡片能进入一道题。
- [ ] 题库存在“已入库题目 / 近10年公开整卷”两个明确入口。
- [ ] 已入库题目可按题目、题型或标签搜索。
- [ ] 手工导入仍可作为兜底入口。
- [ ] 手工粘贴完整真题时优先识别“材料一 / 材料1 / 给定资料1”等显式材料标题；材料内部自然段不得因空行被误拆。
- [ ] 可选老师/机构参考答案能保存，但不会在作答阶段显示。
- [ ] 内置短题进入作答页时明确提示“功能演示题”；不得把 demo 材料误认为正式完整真题。
- [ ] 已入库公开题显示“公开真题”身份；点击“来源”可查看来源站、整卷标题和原始页面。

### B2. 近10年公开整卷

- [ ] 当前年份为 2026 时，公开真题目录范围为 2017—2026；下一自然年自动滚动，不写死年份。
- [ ] 2016 及更早整卷不进入正常公开真题目录；无明确年份来源不自动进入正式目录。
- [ ] 即使本机旧缓存中存在窗口外候选，preview/import 业务层也必须拒绝自动导入。
- [ ] 公开整卷可按年份、地区、标题/卷别筛选，并支持分页。
- [ ] 更新目录只缓存标题、年份、地区、卷别、来源 URL 等元数据，不预先下载全部正文。
- [ ] 同一套卷的普通版、站友版、网友回忆版等按“同卷多版本”分组，不按 URL 重复占位。
- [ ] A/B/C、行政执法、县乡等不同卷别不能被误合并。
- [ ] 同一年同地区的上半年/下半年、春季/秋季等不同批次不能被误合并。
- [ ] 非回忆、非用户提供版本可作为默认优先版本；其他版本仍保留原 URL 供核验。
- [ ] 已有任一版本入库时，整组显示“已有版本入库”，不默认继续制造第二份重复题。
- [ ] “一键初始化近10年题库”能完成主来源扫描 → 待处理整卷结构校验 → 已通过整卷导入；重复运行从既有状态继续，不重复制造题目。
- [ ] 失败/结构阻断整卷不会在一键初始化中无休止重复请求；可通过“重试失败项”显式恢复。
- [ ] 选择某套整卷后才读取正文并进入结构化预览。
- [ ] 预览能看到材料数量、作答题数量、每题题型、分值、字数和解析警告。
- [ ] parser 有 warning 时禁止绕过校验强行导入。
- [ ] 用户确认卷面结构后，一套整卷可一次导入全部作答题。
- [ ] 小题只保存题干明确引用的材料范围；文章写作保留整卷全部材料。
- [ ] 小题引用的材料号若在整卷解析结果中不存在，自动导入必须 fail closed，不能静默改成整卷材料。
- [ ] 导入中断后重试不会生成重复题；同一来源 + 题号使用稳定 Question ID。
- [ ] 导入成功后无需刷新整个应用，新题立即出现在“已入库题目”。
- [ ] 网友/考生回忆版必须保留“回忆版”标识，不与普通来源混淆。

### B3. 首个真实整卷固定验收：2025 国考副省级

> 固定验收来源：公开真题库 `https://gwy.gkzhenti.cn/paper/1743902341589`。本节只记录结构预期，不把第三方整卷正文提交到 GitHub。

- [ ] 公开来源扫描后能发现“2025 年国家公考申论副省级”整卷，并保留原始来源 URL。
- [ ] 结构预览识别 **4 则材料、5 道作答题**，整卷无未解决 parser warning。
- [ ] 第1题：15 分、≤350 字、材料1、题型为“综合分析”。
- [ ] 第2题：10 分、≤300 字、材料2、题型为“综合分析”。
- [ ] 第3题：20 分、≤400 字、材料3、题型为“贯彻执行”。
- [ ] 第4题：20 分、≤400 字、材料4、题型为“提出对策”。来源页面存在“给定 资 料 4”式异常空格，parser 仍必须识别材料4，不得因此产生 warning。
- [ ] 第5题：35 分、1000—1200 字，按 1200 字上限入库，题型为“文章写作”，保留整卷4则材料。
- [ ] 正式导入后，第1—4题分别只携带材料1、2、3、4；第5题携带全部4则材料。
- [ ] 5道题均可从题库打开；题目来源追溯均指向同一原始整卷页面。
- [ ] 对该整卷重复执行扫描/初始化不会再生成第二套重复题。

## C. 实战作答页

### C1. 材料阅读

- [ ] 作答前默认是“材料 + 题目/稿纸”两栏；提交后才展开批改结果，不长期占用阅读宽度。
- [ ] 材料正文使用适合屏幕长时间阅读的中文无衬线字体体系（Microsoft YaHei / PingFang SC 等）。
- [ ] 默认字号约 17px、字重约 500、左对齐、无额外字距，文字清晰且不松散。
- [ ] `A- / A+ / 默认` 字号控制真正作用于材料正文；显示数值和实际字号同步变化。
- [ ] 材料区不显示“本材料多少字 / 总共多少字”等阅读干扰信息。
- [ ] 多材料采用顶部材料导航、上一则/下一则和查看全部；切换材料后阅读位置回到该材料顶部。
- [ ] 完整长材料在材料区独立滚动，不把答题区或整页撑坏。

### C2. 文本标记

- [ ] 记号笔支持黄 / 蓝 / 绿 / 粉等低饱和高亮颜色。
- [ ] 下划线可正常标记材料原文。
- [ ] 标记后正文不跳动、不改变原文字序。
- [ ] 可以撤销最近一次文本标记。
- [ ] 点击已有标记后可以只删除当前标记，不应只能“一键清空全部”。
- [ ] 退出题目再重新进入，高亮/下划线和颜色仍然存在。
- [ ] 文本标记不会进入 AI 的原材料正文，不应污染评分输入。

### C3. 字符锚点自由画笔 V1

> 当前代码已实现字符锚点矢量笔迹，但尚未完成真实 Windows/WebView2 人工验收；在专项验收通过前不宣称“重排稳定性已验证”。

- [ ] 工具栏存在“画笔 / 橡皮 / 撤销笔迹”，与文本记号笔/下划线互斥，不会同时抢事件。
- [ ] 画笔可以直接在材料文字上圈、划、连线；不是截图或 viewport canvas。
- [ ] 笔迹数据保存为“字符 offset + 相对字符光标的 dx/dy”矢量点，不保存绝对屏幕坐标。
- [ ] 橡皮点击/划到一条笔迹附近时只删除该整笔，不一键清空所有笔迹。
- [ ] “撤销笔迹”只撤销最近一笔，不影响文本高亮/下划线。
- [ ] 退出题目再进入后笔迹恢复。
- [ ] 从 17px 调到 22px，再调回 17px，笔迹仍跟随原文字位置，不能停在旧像素坐标。
- [ ] 改变窗口宽度触发材料重新换行后，笔迹应跟随所锚定字符重新布局。
- [ ] 长材料上下滚动后，笔迹与文字不能发生 viewport 漂移。
- [ ] 材料1/材料2切换、查看全部后再返回，笔迹仍绑定到各自 materialId。
- [ ] 已有高亮文字上使用自由画笔时，高亮 span 不抢走 pointer 事件。
- [ ] 提交训练时练习元数据中的标注数量包含文本标记和已提交笔迹数量。

### C4. 计时器

- [ ] 顶部计时器可以开始、暂停和归零。
- [ ] 计时显示稳定，无明显跳秒或页面切换造成异常倍速。
- [ ] 提交后计时停止。
- [ ] 每次提交会保存本题实际耗时和本题标注数量的练习元数据。

### C5. 稿纸作答

- [ ] 作答区表现为申论答题纸网格，而不是普通空白 textarea。
- [ ] 稿纸网格与文字输入层属于同一滚动坐标系；开始输入后网格仍持续可见。
- [ ] 100% Windows 系统缩放下，中文输入应基本保持“一字一格”的视觉节奏。
- [ ] 当前基线为约 32px 方格、18px 答题字体、32px 行高；横向字符步进与格宽保持一致。
- [ ] 连续输入、换行、退格、复制粘贴均正常，不能为了模拟稿纸破坏输入体验。
- [ ] 长答案向下滚动后，文字与网格不能发生明显漂移。
- [ ] 输入答案后草稿自动保存；退出再进入能恢复。
- [ ] 字数统计正确，超过字数上限有明显提示。

### C6. 提交与批改

- [ ] 提交前不泄露评分要点。
- [ ] 提交后才展开结构化批改结果。
- [ ] 批改结果明确标识当前是否为 mock / remote，以及 `uncalibrated` 状态。
- [ ] 非作文真实题提交到 remote provider 时进入 Shenlun Grader Skill，而不是绕过 Skill 直接请求模型。
- [ ] Stage 1—4 不读取已保存参考答案；只有显式 Stage 5 才允许做参考答案交叉核验。
- [ ] 本次提交进入训练记录，历史记录里的 review 是提交时冻结快照。
- [ ] 文章写作暂不使用当前“小题材料点 → rubric → 逐点映射”远程评分流程；系统应明确阻断，而不是生成看似正式的作文数值分。

## D. 复盘与历史

- [ ] 训练记录能看到原始答案、得分、时间和当时的 review snapshot。
- [ ] 点击“再做一次”可以重新进入题目。
- [ ] 错题复盘只聚合 missed / partial 点，不把已覆盖点当错题。

## E. 本地数据

- [ ] 关闭应用再打开：导入题、训练记录、草稿仍存在。
- [ ] 关闭应用再打开：材料高亮/下划线及颜色仍存在。
- [ ] 关闭应用再打开：字符锚点笔迹仍存在。
- [ ] 关闭应用再打开：公开真题目录、整卷导入状态和题目来源关系仍存在。
- [ ] 同一公开整卷重复更新目录，不得把 `reviewed / imported / rejected` 状态重置为 `discovered`。
- [ ] 设置页显示桌面端使用 SQLite；V8 应包含 `practice_ink_strokes`。
- [ ] 浏览器开发模式仍能 fallback 到 localStorage，不影响桌面数据设计。

## F. Remote AI 安全与协议验收

> 没有 API key 时，本节可以先跳过，不影响其他功能验收。

- [ ] Remote AI 默认关闭。
- [ ] 浏览器模式不能启用需要密钥的远程评分。
- [ ] 桌面版 API key 保存后输入框立即清空。
- [ ] 应用没有任何“读取并显示明文 API key”的入口。
- [ ] “测试连接”只验证连接与结构化 JSON，不宣称评分质量已验证。
- [ ] 正式启用前运行“完整自检并启用 AI 批改”；自检使用短内置题真实执行材料盲抽 → rubric → 答案映射 → 字数审计，并且不写训练记录/Human Gold。
- [ ] 完整自检通过后的报告使用当前 `shenlun-grader-skill@0.3.0`，provider kind 为 remote。
- [ ] Stage 3 的 `errorCodes` 只能返回 `error-taxonomy.json` 中的正式代码；结构化 schema 不接受自造错误码。
- [ ] 一个正确完整覆盖的 rubric 点允许 `errorCodes: []`，不得强迫模型为 hit 点制造错误类型。
- [ ] Remote workflow 失败时不会伪造成功结果，也不会自动启用 provider。
- [ ] 当前总分仍标记 `uncalibrated`；完整自检成功只表示 provider 能执行批改协议，不代表已经校准成官方阅卷等值分。

## G. Benchmark Lab / Human Gold

- [ ] 真实本地题作答后可以形成 Benchmark Draft；内置 synthetic 样题不会自动混入正式 calibration。
- [ ] Benchmark Draft 的题目、材料、原始答案与训练时一致。
- [ ] 公开题来源的机构/网站参考答案不得自动成为 Human Gold。
- [ ] Human Gold 标注页面不读取 AI review。
- [ ] H1：先做材料信息点盲抽。
- [ ] H2：Rubric 必须回指 H1 材料点。
- [ ] H3：逐 Rubric 标 hit / partial / missed。
- [ ] H4：可录入真实人工评分者与分数，并分配 calibration / holdout。
- [ ] H5：完成盲标前参考答案正文不可见；首次揭示时间被记录。
- [ ] 完成 adjudication 后 case 在普通 Lab 中只读。

## H. Model Run / Human Alignment

> 需要已完成 Human Gold 的 case，并配置可用 remote provider。

- [ ] Draft Human Gold 不能运行 benchmark experiment。
- [ ] 每次模型实验生成新的 immutable Model Run，旧 run 不被覆盖。
- [ ] Model Run 冻结 provider / model / protocol / reasoning / workflow / promptset / scoring policy。
- [ ] 当前题型/错误 taxonomy Prompt 条件记录为 `shenlun-stage-prompts@0.3.0`；不同 promptset version 的 run 不混算。
- [ ] 默认实验不注入参考答案；只有显式 Stage 5 实验才注入。
- [ ] Human Alignment 只能建立 ID 对应关系，不能修改模型原始 score / status / error code / diagnosis。
- [ ] 真正的模型漏点可以标为 unmatched Gold；模型额外点可以标为 unmatched Predicted，不能被迫硬匹配。
- [ ] Alignment adjudicated 后锁定。
- [ ] Validation report 只接受 adjudicated Human Gold + immutable Model Run + adjudicated Human Alignment。

## I. 视觉与交互验收

- [ ] 页面没有横向溢出、遮挡、元素重叠或按钮被裁切。
- [ ] 主标题、正文、辅助信息的视觉层级清楚，不像“后台管理模板”。
- [ ] 同类卡片、表单、按钮、状态徽章的圆角、间距、字号一致。
- [ ] 长材料、长答案、长来源目录都有合理滚动或分页，不把整页撑坏。
- [ ] Empty / Loading / Error 状态都有明确文案。
- [ ] 训练主流程保持克制，Benchmark / 来源管理等高级工具不挤占正常作答空间。

## 验收结论建议

每次验收只给三种结论：

1. **通过**：核心流程全部通过，只有不影响使用的视觉微调。
2. **有条件通过**：核心功能可用，但存在明确需要修的非阻断问题。
3. **不通过**：安装、数据持久化、作答闭环、公开真题导入、评分安全边界或关键页面存在阻断问题。

不要因为 CI 通过就直接判“通过”；CI 只证明自动化检查，不替代真实桌面环境验收。
